# 开发板调试工作台

面向 STM32、MSPM0、ESP32 等开发板的本地实践项目：按项目管理串口数据、波形、异常规则、调试记录和资料。由 AI 辅助制作，支持 USB 串口，并非示波器或 ST-Link 的替代品。

## 串口数据约定

开发板通过 USB 串口每行发送一个 UTF-8 JSON 对象，并以换行符结束，例如：

```text
{"temperature":23.5,"voltage":3.28}
{"temperature":24.0,"voltage":3.25}
```

顶层数值字段会作为波形通道；字符串、布尔值和嵌套对象不会画成波形。非 JSON 或无数值字段的行计入无效行数。波形横轴是接收顺序，时间是电脑接收时间；不保证固定采样频率，不能用于精确时序或高频测量。需要更改格式或精确测量时应使用相应协议与仪器。

仓库的 `examples/esp32s3-demo` 是使用 ESP-IDF 编译的示例固件，定期输出 `count`、`voltage` 和 `alarm`。其中电压为模拟数值，不是实际测量。构建或烧录前请先确认开发板型号，并备份原固件；示例只包含源码，不包含其他设备的固件或个人数据。

## 运行

双击 `启动.bat`，然后访问 http://127.0.0.1:18763/。首次打开会自动进入「独立调试」空间，无需创建项目即可连接串口、查看波形和记录资料；也可新建项目并切换数据归属。接入开发板后，刷新串口列表，选择端口、波特率和数据格式后连接；确保其他串口软件没有占用该端口。可在串口日志页手动发送文本或 HEX 数据，程序不会自动发送；打开串口时控制线可能触发某些开发板自动复位，具体取决于硬件连接。串口连接期间切换空间，数据仍归属于连接时的空间；如需更换归属，请先断开再切换连接。

更换电脑时，在本目录打开 PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 18763
```

网页服务仅供本机使用，不具备登录、权限或加密传输，请不要公开到网络。数据保存在本目录的 `board-debug.sqlite3` 和 `uploads` 文件夹；这些数据与原设备运维平台及求职工作台独立。

## 已实现

- 独立调试无需项目，也可创建多个项目，记录板卡型号、说明和调试日志、故障记录、测试结果。侧边导航或手机顶部导航可分别进入各功能页面。
- 在网页选择本机串口、波特率、数据位、校验和停止位，持续接收换行分隔的 JSON 数值并绘制最近 300 条；同一时间只能连接一个串口。断开时未结束的行会记录为未解析并丢弃。
- 串口日志页支持单次手动发送最多 1024 字节的 UTF-8 文本或 HEX；文本可选择换行，发送结果仅表示电脑向串口写入的字节数，不代表板端已执行。发送到其他工作区的串口会被拒绝。
- 波形上方展示各数值字段的最新值、与上次的变化和当前规则判断，可点击切换通道。统计与波形仅针对最近 300 条采样。
- 串口日志显示最近 200 行及解析状态，仅保留在内存中；新连接会清空日志，超过长度的行会被忽略。可筛选、冻结显示并导出当前列表；冻结显示不停止串口采集。波形也可冻结显示并恢复实时。
- 按通道设置上下限；越界生成事件，连续越界不重复生成，恢复范围后标记恢复。规则从创建后的新数据开始生效。
- 在「测试记录」填写测试条件、预期、实际和结果，每次执行保存一条；可在「数据与报告」导出当前空间的完整采样 CSV 和调试 Markdown 报告。CSV 每个通道占一行，时间为电脑 UTC 接收时间，图表的统计只覆盖最近 300 条采样。
- 「数据与报告」可下载所有空间的 ZIP 备份，包含数据库快照和已上传文件；仅保存本地路径的资料仍需另行备份原文件。该版本尚未提供网页一键恢复；恢复时先停止服务并另存原数据库和 uploads，再从备份 ZIP 中还原同名数据库与 uploads 文件夹。
- 上传单个不超过 25 MB 的文件并下载；也可单独保存本机路径并复制。记录路径不会复制文件，原文件移动后路径可能失效。
- 整理当前项目、近期数据、异常和记录，供复制到聊天助手；未连接 AI 服务，不会自动发送。

## 硬件调试（实验功能）

「硬件调试」页面通过本机已启动的 GDB 服务连接目标，提供添加或移除断点、继续、暂停、单步、读取简单变量和寄存器；暂停后会尝试显示本机对应源码行。它不会启动 GDB 服务，也不会自动下载、擦除或烧录固件。连接、暂停、单步和断点操作会影响目标程序运行；请确认板子处于可控环境。变量和寄存器是目标暂停时的一次读取，运行后需要重新读取。源码路径、行号和固件必须匹配；无法找到源码时请检查编译时的调试信息和文件位置。

使用前需要真实开发板和调试连接、对应的 GDB 可执行程序，以及与板上固件完全匹配且包含调试符号的 ELF 或 AXF 文件：

- **ESP32-S3**：通过板载 USB-JTAG，使用 ESP-IDF 的 OpenOCD 和 `xtensa-esp32s3-elf-gdb`。先启动对应 GDB 服务；常见端口为 3333，实际以服务配置为准。[乐鑫官方连接说明](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-guides/jtag-debugging/configure-builtin-jtag.html)
- **STM32H723ZGT6**：通过 ST-Link，使用支持目标的 ST-LINK GDB Server 或 OpenOCD，以及 `arm-none-eabi-gdb`。常见 ST-LINK GDB Server 端口为 61234，实际以服务配置为准。[ST 官方服务说明](https://www.st.com/resource/en/user_manual/um2576-stm32cubeide-stlink-gdb-server-stmicroelectronics.pdf)

服务与工具需由用户自行安装和启动；Keil 生成的 AXF 是否可被所选 GDB 正确识别取决于编译工具、调试信息和 GDB 兼容性。工作台只连接 `127.0.0.1`，禁止自动加载 GDB 脚本；不提供程序烧录或任意 GDB 命令。已在 ESP32-S3 演示固件及 STM32H723 的 Agr_IAMV 固件上验证连接、断点和读取；STM32 网页实测了断点、变量、寄存器、源码单步、暂停和继续。ESP32 单步浮点代码时曾进入异常处理，仍需排查。其他固件及配置不能视为已验证。

## 验证与边界

自动化测试主要使用模拟串口和临时数据库；另有可选的 ESP32 实板串口测试。接入真实板卡时应确认串口号、波特率、编码和每行换行。异常提示仅根据人工设置的阈值，不能证明故障根因。建议通过示波器、万用表或其他仪器进一步测量。

运行测试：`.\.venv\Scripts\python.exe -m pytest -q`。先亲自操作、阅读和修改代码，再依据实际参与如实写入简历，并说明 AI 辅助开发。

### 可选：真实 ESP32-S3 串口自动化测试

将本项目的 ESP32-S3 演示固件运行在开发板上，确认没有其他程序占用串口，然后在 PowerShell 中执行（按实际端口修改 COM7）：

```powershell
$env:BOARDLAB_TEST_PORT = 'COM7'
.\.venv\Scripts\python.exe -m pytest -q test_hardware_integration.py
Remove-Item Env:BOARDLAB_TEST_PORT
```

测试使用临时数据库，仅采集演示固件的 JSON，不发送数据或烧录。打开串口可能导致部分硬件复位；演示数据中的电压是模拟值。未设置环境变量时该测试会跳过。

### 可选：Docker 本地部署

安装并启动 Docker Desktop 后，在项目目录执行 `docker compose up --build`，使用 http://127.0.0.1:18763/。容器只映射到本机，数据库和上传文件保存在独立的 Docker 卷中，不会自动导入本机原有数据；停止容器不会删除卷。使用 `docker compose down -v` 会删除卷内数据，不要在需要保留数据时执行。

Docker 模式用于验证网页与后端部署：Windows 的 COM 口、宿主机 GDB 和 OpenOCD 不会自动进入 Linux 容器，本配置不支持直接硬件调试；调试板卡请继续使用 Windows 本机启动方式。Docker Desktop 对 USB 设备需额外配置，不能假设普通 COM 口自动可见。
